    fix(deploy): restore real client IP behind a trusted front proxy
    
    When another TLS-terminating reverse proxy sits in front of nginx,
    $remote_addr is the proxy's address, so X-Real-IP is the same for every
    user: the login/register IP rate limits become global and audit logs
    only record the proxy.
    
    Add an opt-in TRUSTED_PROXY_CIDR (comma separated addresses/CIDRs).
    An nginx entrypoint script turns it into set_real_ip_from /
    real_ip_header X-Forwarded-For / real_ip_recursive on, so nginx itself
    rewrites $remote_addr and the backend (RequestInfo) is unchanged.
    When unset (default) no config is generated, so behaviour is identical
    to before and forged X-Forwarded-For is ignored. Invalid entries make
    the container fail to start instead of being silently dropped.
