# 界面设计规范：流转单

本文是 Web 端（`frontend/`）与移动端（`mobile/`，H5 + 微信小程序）界面的统一设计依据。颜色、字号、圆角等一律使用 token，不在组件里写死色值。

## 1. 设计立意

企业审批的原型是一张纸质「呈批单」：单据头写明单号、事由、金额，下方一排签批栏，每一级负责人在自己的格子里签字、盖章，单据在各个办公桌之间流转。界面借用这张单据的语汇：

- **单据**：申请详情像一张单据，有单据头（类型、单号、标题、申请人、金额）和横线分隔的字段区。
- **签批栏**：审批链路画成一排格子。已办的格子写着处理人与时间，当前格子用虚线框表示「正在等谁」，未到的格子留空。这是整个界面唯一的视觉重点。
- **盖章**：用户同意、驳回时，对应格子里落下一枚章（唯一一处由操作触发的动画）。详情页单据头在终态（已通过 / 已驳回）显示一枚略微倾斜的章。

其余地方保持安静：颜色低饱和，没有渐变、阴影和装饰性动画。

## 3. 字体与字号

- 正文：系统无衬线 `"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC", system-ui, sans-serif`。
- 标题：宋体（公文标题惯例），`"Source Han Serif SC", "Noto Serif CJK SC", "Noto Serif SC", "Songti SC", "STSong", serif`，字重 600。**只用于**页面主标题、单据标题、工作台问候语，其余一律无衬线。
- 数字：金额、单号、计数一律 `font-variant-numeric: tabular-nums`；金额右对齐。单号用正文字体，不用等宽字体。
- Web 字号阶：12 / 14 / 16 / 21 / 28 px，正文 14px，行高 1.6；移动端：24 / 28 / 32 / 40 / 52 rpx，正文 28rpx。

文案规则：

- 不用「A · B · C」中点拼接元信息，用间距分开的独立文字。
- 链接、按钮不追加「→」或右箭头图标；写清动作：「查看全部待办」「去处理」「填写申请」。
- 按钮文字与结果提示一致：按钮「同意」→ 提示「已同意」；「撤回」→「已撤回」。

## 4. 形状与层次

- 圆角分级：面板 / 单据 6px（移动端 12rpx），按钮与输入框 4px（8rpx），标签 2px（4rpx），头像圆形。
- 阴影：面板不用阴影，靠 1px `rule` 边框和底色区分层次；只有浮层（下拉、对话框、通知、底部面板）用 `0 8px 24px rgba(34, 48, 58, 0.12)`。
- 状态在列表中用「6px 圆点 + 文字」表示，不用整块底色标签；详情页单据头用描边小框。
- 焦点：`:focus-visible` 统一 2px `primary` 外框，偏移 2px。

### 移动端

- 页面底色 `paper`，导航栏同底色、黑字；列表卡片白底 12rpx 圆角、无阴影，卡片间距 16rpx。
- 首页：问候语（宋体）→「待你审批」前 3 条 →「我的申请」状态条 → 发起入口四列网格 → 最近通知。
- 详情页：单据头 + 横向可滚动的签批栏 + 字段区 + 流转记录。
- tabBar：文字 `#6C777E`，选中 `#3E5C76`，线性图标两色重绘。

## 6. 交互

### Web：鼠标

1. **列表行**（待办、我的申请、本部门申请、已办）：整行可点进入详情，`cursor: pointer`；悬停时行底变 `paper`、左侧出现 3px `primary` 竖线，并显出行内操作（处理 / 查看 / 催办）。行内操作在 `:focus-within` 时也显示；`@media (hover: none)` 下常显。按住 Ctrl / ⌘ 或中键点击在新标签页打开。
2. **签批栏与流转记录联动**：鼠标移到某个签批格，下方流转记录中属于该节点的条目高亮，并弹出该节点的审批意见；反过来移到流转记录条目上，对应签批格高亮。
3. **单号复制**：悬停单号出现「复制」提示，点击复制并提示「已复制单号」。
4. **发起入口**：悬停时边框变 `primary`、说明文字完整显示；按下时下沉 1px。
5. **附件区**：支持把文件拖进上传区，拖入时上传区虚线框变 `primary`、底色变 `primary-tint`。
6. **统计图表**：悬停显示数值提示；悬停图例高亮对应序列，其余序列淡出。
7. **侧边栏**：可折叠；折叠后悬停图标弹出菜单名。

### Web：背景「格纸」

页面底色上铺一层很淡的点阵（印刷表格用的格纸），它跟着鼠标动：

- **点阵**：间距 20px，点半径 1px，颜色 `rule-strong`、透明度约 0.6。只铺在主内容区背景（面板之间、四周留白）和登录 / 注册页左半边；白色面板盖在上面，不影响阅读。
- **跟随**：以光标为中心、半径 140px 内的点，按 `(1 - d/R)²` 的强度变大到 1.8px，颜色向 `primary` 过渡（透明度最高 0.55），并向光标偏移最多 3px。光标位置做缓动跟随（每帧逼近 18%），所以点阵像被轻轻拖动。光标附近再叠一层半径 220px、很淡的白色径向光（透明度 ≤ 0.35），让纸面「被照亮」。
- **离开**：鼠标移出区域时，影响在 300ms 内淡出。
- **点击涟漪**：在背景空白处（不是面板、按钮上）按下，以按下点为圆心，点阵像水面一样荡开：波前以约 0.24px/ms 向外扩散（约 1000ms 到 240px）；每个点按到圆心的距离 d 与波前半径 r 计算位移 `offset = A · sin(2π·(r − d)/λ) · exp(−((r − d)/σ)²)`（仅 d ≤ r 的波后区域，λ ≈ 36px、σ ≈ 48px），沿半径方向推拉，最大振幅 A₀ = 5px，并随时间线性衰减到 0（A = A₀ · (1 − t/T)，T = 1000ms）；位移越大的点越大（最大 1.8 倍）、越接近 `primary`（透明度最高 0.5）。不画线条或光圈。连续点击可叠加，最多同时 3 个涟漪，超出时丢弃最早的。`prefers-reduced-motion` 和触屏设备不触发。
- **性能**：静态点阵先画到离屏 canvas，每帧只重绘光标附近与各涟漪覆盖范围的矩形区域；指针静止且缓动收敛后停止 `requestAnimationFrame`；页面不可见时停止。按 `devicePixelRatio` 绘制，随容器尺寸变化重建。
- **降级**：`(hover: none)` / `(pointer: coarse)` 设备和 `prefers-reduced-motion: reduce` 只画静态点阵，不响应指针。

### Web：登录页「流转演示」

登录 / 注册页左半边的三格示意图（部门负责人、财务审批、企业负责人）演示一张申请如何逐级流转：

- **自动循环四步**，每步 2400ms：① 部门负责人「处理中」，其余「待流转」；② 部门负责人「已同意」，财务「处理中」；③ 前两格「已同意」，企业负责人「处理中」；④ 三格全部「已同意」，行尾落一枚「已通过」小章（描边、`success` 色、`rotate(-6deg)`）。第 ④ 步停 3200ms 后，三格一起淡回「待流转」，从 ① 重新开始。
- **格子样式**沿用签批栏：「处理中」为 `primary` 虚线框 + `primary-tint` 底；「已同意」为实线框，格内落一个「同意」小章（1.15 → 1 缩放、透明度 0 → 1，`--eas-dur-stamp`，与详情页盖章同一动作）；「待流转」文字 `ink-3`。框线与底色过渡 `--eas-dur` + `--eas-ease`。
- **鼠标**：指针在示意图上时暂停；移到第 i 格时立刻切到「第 i 格处理中」那一步（移到最后一格之后的「已通过」章上切到第 ④ 步）；移开后从当前步继续计时。
- **说明文字**：示意图下方一行 12px `ink-2`：「审批流程」。示意图本身对读屏隐藏（`aria-hidden`），说明文字可读。
- **降级**：`prefers-reduced-motion: reduce` 时不自动播放，停在第 ② 步，鼠标悬停切换仍可用（无过渡）；页面不可见时暂停计时；组件卸载时清理计时器。

### Web：登录页分栏可拖动

登录 / 注册页左右两栏之间的分界线可以拖动：

- **手柄**：分界线两侧各 6px 的不可见热区，`cursor: col-resize`。悬停或拖动时，分界线变成 2px `primary`，垂直居中出现一个 4×28px 的圆角握把（`primary`）；平时只是 1px `rule`。
- **拖动**：按住后左右拖，右侧表单栏宽度跟手变化，范围 380px 到视口宽度的 60%，且左侧说明栏不小于 360px；拖动中不加过渡、禁止选中文字。左侧背景格纸随容器尺寸自动重绘。
- **记忆与复位**：松手后把表单栏宽度存到 `localStorage`（`eas.auth.formWidth`），下次打开沿用（读出的值仍按当前视口夹紧）；双击分界线恢复默认 540px（带 `--eas-dur` 过渡）。窗口缩放时重新夹紧。
- **键盘**：手柄可 Tab 聚焦（`role="separator"`、`aria-orientation="vertical"`、`aria-valuenow/min/max` 为表单栏宽度），左右方向键每次 16px，Home / End 到最小 / 最大，聚焦时显示和悬停相同的样式。
- **窄屏**：880px 以下只显示表单栏，不出现手柄。

### 移动端：手指

1. **按压反馈**：所有可点的卡片、列表行、宫格用 `hover-class`（底色变 `paper-deep`、缩放 0.985，`hover-stay-time` 60ms）。
2. **左滑操作**（自建 `SwipeCell`，H5 与小程序都用 touch 事件实现）：
   - 消息：左滑出现「标为已读」。
   - 我的申请：审批中左滑出现「催办」「撤回」；草稿左滑出现「删除」。调用与详情页相同的接口，弹出同样的确认框。
   - 同一时间只展开一个；点别处或开始滚动时收起。
3. **横滑切换标签**：待办 / 已办、我的申请的状态筛选，在列表区左右滑动即可切换；分段控件的选中块随之滑动（200ms）。只在横向位移 > 60px 且大于纵向位移 1.5 倍时触发，不影响竖向滚动。
4. **滑动同意**（自建 `SlideConfirm`）：审批面板中「同意」是一条滑轨，把滑块拖到最右端（≥ 90%）才提交；中途松手滑块弹回。成功时短振动（`uni.vibrateShort`）。单点滑块提示「向右滑动以同意」。「驳回」保持按钮，填写理由后提交。
5. **底部面板下拉关闭**：面板顶部有拖动条，面板跟手下移，下拉超过 120rpx 或快速下划时关闭，否则回弹。
6. **长按单号复制**：详情页单号长按复制并提示。
7. **签批栏**：横向滚动；点一个格子在下方展开该节点的审批意见。
8. 保留现有的下拉刷新、上拉加载。

## 7. 动效

- 只做三类：对操作的回应（展开、收起、滑动跟手、回弹、选中块滑动）、背景格纸跟随鼠标、登录页流转演示，以及「盖章」。不做页面载入动画、卡片悬停浮起、骨架闪光以外的装饰性动效。
- 时长 120–240ms，缓动 `cubic-bezier(0.2, 0, 0, 1)`。
- 盖章：章从 1.15 倍缩到 1 倍，同时透明度 0 → 1，240ms，只播一次。
- `prefers-reduced-motion: reduce` 时，所有过渡改为瞬时，盖章直接显示。

## 8. 质量底线

- 正文对比度 ≥ 4.5:1（墨色在白底 13.5:1，主色 7.0:1）；`ink-3` 只用于 12px 以上的辅助信息。
- 触控目标 ≥ 88rpx（移动端），可点元素 ≥ 32px（Web）。
- Web 在 768px 以下切换为抽屉菜单，列表行内操作常显。
- 可键盘操作：所有自建可点元素用 `button` / `a`，或补齐 `tabindex` 与回车 / 空格响应。
